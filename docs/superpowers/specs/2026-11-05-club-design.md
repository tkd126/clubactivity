# 동아리 기록 설계

## 사용자 수정 반영

학생 작성은 활동 내용 한 칸으로 통합한다. 날짜와 1·2차시 선택, 비공개 권한, 교사 관리·다운로드는 유지한다. 미리보기는 27명 모두 미작성 상태로 시작하며 사전 예시 기록을 넣지 않는다. 디자인은 사용자가 지정한 아임웹 workflow 템플릿의 흰 배경/청록 버튼/상단 메뉴를 참고한다. 아래 초기 설계의 참여·배움 별도 입력은 이 수정으로 대체한다.

학생 27명이 번호와 개인 비밀번호로 로그인하여 날짜와 1·2차시별 활동, 참여, 배움을 작성한다. 학생은 자신의 기록만 읽고 수정한다. 교사는 27명 전체 기록을 번호순으로 조회하고 미작성자를 확인한다. 교사 메모와 학생별 특기사항 초안은 교사만 열람·수정한다.

GitHub 소스와 Vercel 배포는 사용자 지정이다. 구현은 빌드 없는 HTML/CSS/JS, Vercel Node API, Supabase Auth/PostgreSQL로 한다. Next.js보다 의존성이 적고 브라우저 저장 방식과 달리 기기 간 기록을 공유한다. Supabase와 번호별 내부 이메일 매핑은 구현자 결정이다. 사용자 요청에 따라 추가 질문 없이 진행한다.

API는 Supabase에서 사용자 토큰을 검증하고 테이블 RLS도 학생 본인 또는 교사로 제한한다. 관리자 키는 계정 생성과 비밀번호 재설정에만 서버에서 사용한다. 이름은 수집하지 않는다. 동일 학생·날짜·차시에는 하나의 기록만 유지한다. 저장 실패 시 입력을 유지한다.

교사는 날짜/차시/제출 여부 필터, 27명 세로형 목록, 전체 기간 학생별 조회, CSV 및 AI 요청문 포함 TXT 다운로드를 사용한다. CSV 수식 주입을 방지한다. AI 자동 호출이나 나이스 직접 연동은 하지 않는다. 저장소 미설정 시 오류를 명확하게 표시한다.
